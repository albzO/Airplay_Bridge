# 架构

本文描述当前版本的职责、状态与资源边界。代码入口见[阅读指南](code-reading-guide.md)，运行和验证方法见[测试说明](../test/README.md)。

## 模块与数据路径

| 目录                        | 职责                                                               |
| --------------------------- | ------------------------------------------------------------------ |
| airplay-frontend/src/       | Vue 界面、IPC 校验、会话和诊断状态                                 |
| airplay-frontend/src-tauri/ | 桌面命令、配置、Source 管理、认证、托盘和生命周期                  |
| airplay-core/src/           | WASAPI、持续 Source、转换/漂移、传输、诊断及 CLI                   |
| airplay-backend/            | 原生后端、上游补丁及 Windows 兼容层                                |
| upstream/                   | 固定版本的第三方 Git 子模块                                        |
| test/                       | frontend/backend/core 测试、合成素材；生成内容在忽略的 .artifacts/ |
| scripts/                    | 构建、发行及敏感信息检查                                           |

```text
WASAPI → 解码及左右输入映射 → 持续 Source → 有界订阅队列
  → 会话左右互换 → 有状态重采样/漂移校正 → PCM16 有界队列
  → 独立管道写线程 → 原生后端 → ALAC/加密 RTP/时钟与重传 → 接收端
```

发送格式为 44.1 kHz 双声道 PCM16。Rust 使用 MSVC，原生后端使用 MSYS2 UCRT64，通过子进程管道通信。GUI 直接链接核心库，homepod-test.exe 供独立 CLI 诊断使用。

capture 下的 decode、timeline、metrics、health、diagnostics、clock 和 lifecycle 分别处理解码、时间线、统计、健康、诊断、平台时钟及计数。采集循环保留 WASAPI 获取、包释放和交付顺序；原始摘要与解码在 ReleaseBuffer 前完成，sink 交付在其后。

上游适配采用固定子模块、上下文补丁和本地 Windows 实现。Python 校验/应用补丁及选择编译内容；哈希和输出快照更新见[构建指南](building.md#上游适配变更)。

## 状态与所有权

| 对象或状态                           | 所有者与含义                                            |
| ------------------------------------ | ------------------------------------------------------- |
| Engine.source                        | 应用级持续采集器；提供电平和至多一个串流订阅            |
| Engine.session                       | 准备/播放/收尾占用；资源确认退出后释放匹配编号          |
| Preparing                            | 已预留编号，后台枚举、保存及等待 Source                 |
| Active                               | 桌面准备完成；认证、PCM_READY 和实际传输仍是不同阶段    |
| Expired                              | 准备或停止期限到期，保留占用直到重启                    |
| GuiControl.stop                      | 会话取消请求，不表示资源已经退出                        |
| cleanup_complete                     | false 阻止重连及有冲突的配置操作                        |
| 前端 busy/connected/playing/stopping | 操作占用、PCM_READY、遥测及停止意图，按 session_id 过滤 |

Source 可跨会话存活。停止串流解除订阅，切换来源、关闭采集或退出才停止 Source；会话重新创建转换器、漂移状态、队列和后端。仍在停止的 Source 不能复用或并行重开。

前端不从早到事件猜编号：确认命令返回前最多缓冲 512 条事件，并保留 finished；取得编号后只接收该会话。确认前停止/卸载保留取消意图，迟到编号也单独取消。

成组状态使用短 Mutex，停止和左右互换使用原子标志。全局会话锁内不枚举设备、写盘或等待线程；资源所有者统一安排回收，后续步骤不能另加停止预算。

## 启动取消与设置提交

1. start_stream 在短锁内检查退出/配置占用，预留单调编号和 GuiControl，启动后台工作后返回。
2. 后台检查设备、立体声、端点及声道，保存设置、创建密码服务，复用健康 Source 或创建请求独占的 Source。
3. 慢步骤前后检查取消、退出、编号和期限；Source 稳定后核对并发布资源，进入 Active，再开始协议握手。
4. 准备失败只清理本次新建资源。迟到结果不能激活过期准备或提交到新会话，结束事件仅认领一次。

Preparing 总预算 15 秒，包含 Source 最多 8 秒稳定等待；之后后端握手/密码等待有独立 90 秒限制。到期未确认退出时报告 START_TIMEOUT 或更早的 STOP_TIMEOUT，保留占用；旧调用稍后返回也不自动开放重试。

设置、映射、互换、发现、预览、采集开关和忘记认证策略共用 Operation 互斥，重复请求直接返回忙碌。Preparing 拒绝冲突操作；Active 保留实时映射与互换。

Settings::save_checked 在暂存写入前后检查取消，成功替换 settings.json 是提交点。失败或提交前取消保留旧设置；替换成功后同步内存及路由，即使此时取消也不撤销已提交偏好。文件 I/O 不持有全局会话或设置快照锁。

## 音频完整性与缓冲

预热以连续包和时间线健康判断，静音有效；至少 500 ms 稳定、3 包，间隔超过 250 ms 或故障会重置窗口。Playback 电平/原始包矛盾检查只用于启动，稳定后不因暂停重新开启；重建只在无订阅时尝试，最多三次。

时间线保留 40 ms 空闲交付余量，单次缺口最多 250 ms，60 秒内最多 5 次、累计 500 ms；持续或严重异常停止并记录原始位置/QPC，不放宽时间戳校验。

两级音频队列各按 640 ms、最多 256 块限制，计入正在处理的块；容量不等同实际播放延迟。Source 完整复制数据以脱离 WASAPI 生命周期，每订阅最多回收 32 个、每个容量最多 64 KiB 的 Vec，空闲存储最多 2 MiB；超大包完整交付，用完释放。PCM 字节和互换缓冲在会话内复用。

不合并、拆分或重排输入包，不改变样本位值和帧顺序。左右互换在会话缓冲中交换每帧样本，未互换时借用原输入。重采样器跨包保留滤波历史，漂移控制使用滤波、积分限幅和变化速率限制。测量范围见[性能基线](performance-baseline.md)。

## 通知与认证策略

| 通道              | 限制与策略                                              |
| ----------------- | ------------------------------------------------------- |
| Source 电平       | 每 100 ms 更新，仅保留最新待发送快照                    |
| Source 告警       | FIFO 最多 64 条；最终零电平/错误有专用位置              |
| 会话控制          | FIFO 最多 128 条；就绪、认证、音量、故障不被遥测覆盖    |
| 会话遥测/设备统计 | 按类型/host 合并，合计最多 16 槽；故障诊断进入控制 FIFO |
| 普通展示日志      | 最多 64 条，满时丢弃并计数；原始日志另走日志队列        |
| 最终报告          | 独立位置，排完已接受事件再发送，封闭后续遥测            |
| 单个会话事件      | 序列化最多 64 KiB；含通知状态的报告最多 1 MiB           |

Source 和 GUI 会话各有通知线程，回调期间不持有队列锁。协议先更新原始状态及独立 PCM_READY 通道，再投递日志/通知；音频管线只入队。替换快照取得新序号，PCM_READY 先于后续遥测，结束后不重放旧电平。

控制队列/统计槽满或事件过大时明确请求停止，报告 SOURCE_NOTIFY_FAILED / STREAM_NOTIFY_FAILED；回调异常也报告故障。已接受的控制事件保留，最终位置不被日志挤占。永久阻塞的回调无法安全强杀，不能保证及时送达；超时保留句柄和会话占用。

认证策略另有保存线程，仅接受两台已选设备的明确密码证据，每目标每会话一次尝试。host 最多 128 字节、身份最多 4096 字节，不保存密码或原始事件。回调只登记下标/取错误，不取得策略锁或写盘；保存线程短锁取得副本，锁外写盘，提交成功后发布内存。

remember/forget 失败不提前改变内存，下一会话可重试。错误最多两条、每条 2048 字符，由后续事件或收尾发送 auth_memory_error。忘记策略与启动互斥；期限后不开始下一次写入，已进入系统的写入超时则将 Worker 留在 Session.auth_policy，保留占用。

## 停止错误与日志

首次停止请求建立共享 15 秒截止时间，重复请求只能缩短。正常停止解除订阅、排出滤波尾帧、关闭 PCM 输入、排空已接受的 PCM，再由后端完成尾部静音和 TEARDOWN；采集故障不额外生成尾帧。

后端、PCM/stderr、DACP、诊断/报告、通知、密码管道及策略保存共用期限。日志通常最多共用 250 ms，报告写入最多 250 ms，并预留桌面收尾时间。全进程限时持久化/通知任务最多 8 个；每个 Source 的首次停止预算也不续期。

后端使用 kill-on-close 的 Windows Job Object，应用退出有独立兜底。Source/会话未确认退出时保留资源，拒绝并行重开；取消无法安全中断任意驱动、磁盘或 GUI 回调，期限表示停止等待/报告错误的时机。

stderr 的 reading/eof/failed/cancelled 独立于协议、认证及日志状态；失败保留 ReadFile、原始 Win32 代码和上下文。Win32 995 仅在已请求取消时归入取消；真实故障不因用户停止而隐藏。握手前失败直接返回，进入报告阶段后才生成完整报告。

协议日志使用 128 条有界队列，先脱敏再独立写文件/控制台；首个协议故障由原始状态保留。报告保留协议、采集、读取/PCM 管道及传输/收尾原因，保存失败仍提供 GUI 内存报告。限制见[日志保留](log-retention.md)，契约见[错误代码](error-codes.md)。

## 界面数据与当前边界

App.vue 组合来源、设备及设置视图；useStreamSession 管理会话，useDiagnostics 管理有界日志/摘要和应用累计统计。子视图通过 props/事件连接，不修改发现结果或直接控制音频；设置共用确认快照，失败回退。清空诊断仅清展示摘要，不清设备累计、路径或报告。

portable.flag 选择程序目录下 data/，安装版使用 %APPDATA%/AirPlay Hub；CLI 有独立数据子目录，见[使用说明](ui.md)。keepAwake 同时持有 SystemRequired / DisplayRequired，覆盖预览、托盘及会话；它避免自动熄屏，不提供完整睡眠/恢复支持。

配置/初始化中的驱动调用没有统一响应上限，占用仍阻止重复累积；initialize 的独立枚举不属于 Preparing 预算。合成测量、模拟协议和本地测试不代表真实设备长测通过。

仍有生产入口引用 test/ 启动探针/nonce 自检、Source 日志复用 live::diagnostics、原生标记在多层解析、两套安装清单重复等维护边界。本地 DACP 控制通道的进一步身份认证和跨平台依赖安全审查也需单独验证。后续按所有权和接口逐项整理，不在文档清理时改变实现。
