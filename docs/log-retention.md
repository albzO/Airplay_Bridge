# 日志与诊断保留限制

应用自动生成的日志现在同时限制内存历史、单个文件和日志目录。达到限制时会截断展示、轮转或停止记录，旧记录可能被清理；排查问题时应及时复制相关片段。

## 页面与队列

| 内容 | 限制 | 超限行为 |
|---|---|---|
| 页面会话日志 | 最近 300 条，每条最多 4096 个 UTF-16 单元 | 删除最早记录，长文本加截断提示 |
| 页面诊断摘要 | 最近 120 条，每条最多 4096 个 UTF-16 单元 | 结束/错误摘要也计入，清空后继续接收 |
| 设备累计统计 | 最近 128 个不同设备，每个仅 6 项计数 | 淘汰最早设备，同时移除名称和会话基线 |
| 页面报告 | 紧凑 JSON 的 UTF-8 大小不超过 1 MiB | 显示超限说明，不保留超大报告对象 |
| 协议日志队列 | 128 条，每条脱敏副本最多 8192 字符 | 非阻塞丢弃并计数；原始控制事件继续处理 |
| 逐包 / pipeline / 漂移 / Source 队列 | 分别 1024 / 16 / 16 / 32 条 | 非阻塞丢弃并计数 |
| CLI 后端诊断 | 128 条通道，每条最多 8192 字符；至多 13 类首条结果标记 | 重复统计不累积，按批处理以继续检查退出/超时 |

设备统计从原始协议行解析，展示优先使用脱敏副本。重复累计值不重复加计；部分、非法或负值不覆盖已知基线。重连清空会话基线及会话展示，保留应用累计设备统计；切页不重置。`useStreamSession` 继续负责会话编号过滤，`useDiagnostics` 只接收验证并归属后的事件。清空显示仅清除诊断摘要。

## 落盘

| 文件 | 上限与保留方式 |
|---|---|
| 详细协议日志、CLI 后端日志 | 每文件 8 MiB，达到后停止该文件记录 |
| 仅故障协议日志 | 每文件 256 KiB，保留既有最近上下文策略 |
| pipeline 与逐包 JSONL | 每段 8 MiB，当前加前 3 段，单组最多 32 MiB |
| 漂移 JSONL | 每文件 8 MiB，达到后停止记录 |
| Source 启动 JSONL | 每段 2 MiB，当前加前 1 段，追加前检查并轮转 |
| 音量日志 | 详细模式 1 MiB，仅故障模式 64 KiB |
| UI 故障日志 | 每文件 64 KiB |
| 串流 JSON 报告 | 每文件 1 MiB，超限不创建/覆盖文件 |

`log_store.rs` 在打开新日志时，将同一日志目录中可识别文件控制在 **256 MiB、256 个文件**以内；按修改时间从旧到新回收。当前进程正在写入的文件按其完整上限预留空间，防止创建时很小、后续增长超出目录预算。无法安全回收足够空间时拒绝新日志，返回 `LOG_LIMIT`，不删除活动文件。

只识别带数字编号的 `live-*`、`backend-*`、`ui-fault-*` 日志/报告及其固定轮转后缀，还有两个 Source 启动文件。清理只操作规范化目录的直接普通文件，不递归，不清理符号链接、子目录或其他命名的文件。Windows 日志句柄禁止删除和替换，另一进程无法清理正在写入的文件；因文件被占用而无法删除时跳过它，仍超限则拒绝新文件。

目录预算由当前进程维护，**没有跨进程共享的预算锁**；多个独立进程同时在同一目录创建/扩展日志时，总量不是严格的原子上限。GUI 与 CLI 默认分别使用各自的日志目录。下一次打开日志会重新检查目录；程序不运行时不会后台清理。升级前已有文件不原地截断，按目录保留规则回收。

## 错误与范围

诊断线程达到文件上限或发生写入错误时，通过对应日志状态报告；音频与协议状态不依赖该线程写盘成功。CLI 与音量达到上限时停止写入，并只提示一次；真实 CLI 磁盘错误仍沿用原有失败路径。报告超限仍发送内存事件并保留 `report_write_error`；协议/采集/管道等原有首因优先。

单条记录先检查容量，再写入，容量不足不会写入半条 JSON；这不保证磁盘故障、进程崩溃或底层部分写入时的文件完整性。日志 250 ms 收尾规则不变，无法取消已经阻塞的系统 I/O；最终报告仍同步保存，没有硬超时。

这些限制针对应用自动日志及其保留历史，不限制外部重定向的控制台文件，也不自动删除用户主动生成的 WAV、PCM 及配套采集/转换报告、配置或认证数据。IPC 原始事件、序列化临时对象和系统缓冲不等同于页面保留历史，未据此宣称进程总内存有上述硬上限。

回归覆盖真实临时文件的大小/数量回收、活动文件与陌生文件保护、Windows 打开句柄保护、Source 临界追加轮转、超大报告的首因保留，以及真实页面的突发日志、摘要结束和清空范围。未注入真实磁盘压力或执行多进程预算竞争长测。
