## 源码获取与分发

主仓库使用子模块引用第三方源码；本地构建仍需下载这些依赖。保留上游版权文件头和许可证，不将生成的适配版本声明为全部原创。

分享源码时提供子模块地址、固定提交和初始化步骤。GitHub 自动生成的源码 ZIP 不包含子模块内容；相应构建输入的获取方式见 [构建指南](building.md)。如果具体许可证要求提供对应源码，应按实际授权条件提供，不以一个可变化的上游分支链接代替固定源码信息。

## 二进制发布清单

为一个具体版本准备发行包时，应核对：

- [x] 自有代码采用 Apache-2.0，并通过 LICENSE、NOTICE 和本文说明适用范围。
- [ ] bplist 固定版本的授权依据已明确。
- [ ] 记录项目提交、第三方提交、锁文件与实际打包 DLL 的版本。
- [ ] 列出发行包中包含的第三方组件，而非照搬完整上游程序的组件表。
- [ ] 按各组件要求随包提供许可证、版权声明、NOTICE 及必要的修改说明。
- [ ] 如适用，提供对应源码和可复现的构建步骤。
- [ ] 排除个人设备清单、日志、录音、凭据和本机配置。

现有 `dist/licenses/` 仅包含构建脚本目前复制的部分材料，不是完整审查的证明。1.0 正式版的版本标签不改变第三方许可证条件，也不代表表内待确认事项已完成。
