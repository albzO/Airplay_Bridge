## 具体缺陷及证据（修复前）

### F1 / P2：互换命令失败后，运行中的声道可能已经交换

位置：`airplay-frontend/src-tauri/src/main.rs:466–478`；页面反馈位于 `App.vue:363–371`。映射命令 `main.rs:441–463` 有相同的先变更后保存顺序。

`set_speaker_order` 先更新活动会话的原子开关及内存设置，最后才保存文件。保存失败向页面返回错误，页面保留旧名称，但音频管线已读取新开关。`set_mapping` 也会在保存前修改会话、Source 和内存映射；失败后磁盘偏好仍为旧值。

自证：从当前源码提取这两个命令的完整函数体，注入枚举结果及返回错误的保存函数，以无设备 Rust 探针执行。初始未交换、映射 `[0, 1]`；两个命令均返回错误后，活动开关和内存设置均为 `true`，会话/Source/内存映射均为 `[1, 0]`。另外执行真实页面脚本，让互换 IPC 拒绝，页面开关仍为 `false`。两侧组合表明现有失败语义不能保证一致性；没有借此声称执行过完整 Tauri 音频链路。

方向：确定统一的成功/失败语义。保存失败应保留原有运行状态，或明确返回“运行已改变、保存失败”的独立结果并同步页面；优先采用可回退的更新顺序。永久回归必须检查运行状态、内存设置及文件结果，不能只拒绝 IPC 后检查文字。

### F2 / P2：来源保存失败后仍继续预览，页面与实际来源可能不同

位置：`airplay-frontend/src/App.vue:251–257、265–299`；桌面取设置的位置为 `main.rs:82–120、193–207`。

`selectSource` 先改页面端点和映射；`persist` 通过 `call` 捕获保存错误并正常返回，`sourceChanged` 随后仍调用 `monitor_source`。桌面的 `save_settings` 在失败时保留旧设置，`ensure_source` 又从这些旧设置选择来源。页面可能显示新来源，而预览仍使用旧来源；旧来源事件还会被页面的端点过滤丢弃。

自证：执行真实 `App.vue` 脚本，选择合成单声道来源并令 `save_settings` 失败。调用顺序仍为 `save_settings → monitor_source`，页面端点已变为新来源，映射为 `[0, 0]`，同时显示保存错误。桌面继续读取旧设置的部分由源码顺序确认；没有打开实际设备。下一次开始串流若成功保存设置，可能重新纠正来源，不能据此声称所有串流都会使用错误来源。

方向：保存必须向调用者传播成功/失败；失败时停止后续操作并恢复端点/映射。来源切换还应管理进行中的请求，覆盖失败、重复选择和迟到完成，不仅验证正常的“先保存再预览”。

### F3 / P2：保持唤醒的旧保存失败会回滚较新的选择

位置：`airplay-frontend/src/App.vue:278–284`；`GeneralSettings.vue:73–81` 未在保存期间禁用该开关。

失败处理直接执行 `keepAwake = !keepAwake`，没有保存该请求原值，也没有请求归属检查。用户在第一次保存完成前再次切换，第一次失败时反转的是当前新值；第二次保存成功也不会重新同步页面。

自证：真实页面脚本由开变关、随后变开，两个保存请求均暂存；按请求顺序令第一次失败、第二次成功。最终页面为关闭，第二次接受的设置为开启。无需响应逆序即可复现；IPC 和系统电源操作仍为模拟边界。

方向：增加保存中状态，或使用请求编号及已确认快照，只允许对应请求回滚自己的值。回归覆盖连续点击、第一项失败/第二项成功以及其他设置同时变化。

### F4 / P2：报告写盘失败覆盖协议首因

位置：`airplay-core/src/live.rs:450–466`。

代码已保存 `backend_error`，但在按“协议 → 采集 → 管道 → 退出状态”返回之前，报告序列化/`fs::write` 使用 `?`。报告写盘失败会提前返回，页面收到的是文件错误，原协议故障没有进入最终错误；报告事件也不会发出。

自证：提取当前源码的最终报告/错误选择代码块，以真实 `serde_json` 和 `fs::write` 执行；报告脱敏、GUI、协议状态等依赖使用最小替身，协议首因固定为合成错误。报告可写时返回协议首因；将目标 `.json` 路径预置为目录后，返回 `Access is denied. (os error 5)`，不含协议首因。该探针验证此代码块的优先级，不代表完整串流已运行。

方向：报告落盘错误单独记录，继续保留并返回协议/采集/管道首因；尽可能仍发送内存报告。没有更早故障时，才把报告保存失败作为主要结果。覆盖“协议故障 + 报告失败”“正常停止 + 报告失败”等组合。

### F5 / P3：便携模式日志位置提示使用了安装版路径

位置：`airplay-frontend/src/App.vue:226–229、544`；实际目录选择见 `airplay-core/src/data_dir.rs:7–36`。

`logDisplayPath` 将任何输入路径都显示为 `%APPDATA%/AirPlay Hub/logs/<文件名>`，初始化也固定这一提示。数据目录模块在存在 `portable.flag` 时使用程序所在目录，因此便携用户看到的位置不准确；“打开日志目录”命令本身仍使用正确的数据根目录。

自证：调用真实页面函数，输入 `fixture-portable/logs/live-1.log`，结果仍为 `%APPDATA%/AirPlay Hub/logs/live-1.log`。现有日志 DOM 用例只断言这一硬编码结果，没有覆盖两种目录模式。

方向：由初始化返回的目录/模式生成脱敏位置提示，分别覆盖安装版、便携版和空路径；保留文件名展示和现有隐私边界。
