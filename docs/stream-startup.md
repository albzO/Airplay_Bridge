# 启动准备、取消与配置互斥

2026-10-11，基于 `374f3e8` 优化启动准备。此前 `start_stream` 在全局会话锁内枚举设备、保存设置及初始化 Source；停止命令需要同一把锁，无法及时登记取消。已有 15 秒停止预算从收到请求后开始，不能解决这段等待。

## 启动流程

1. `stream_start::start_stream` 只校验参数形状，在短会话锁内检查退出/配置占用，预留编号、GuiControl 和 Preparing 阶段，启动后台工作后返回编号。编号首次以毫秒时间播种，之后单调递增，不因系统时钟倒退而重复。
2. 工作线程读取设备、检查立体声关系及认证策略，枚举采集端点并校验声道。慢步骤前后核对取消、退出及会话归属。
3. 保存候选设置；初始化密码服务，复用健康 Source 或创建请求独占的 Source，再等待采集稳定。新 Source 此时尚未交给 Engine；复用的预览 Source 继续由 Engine 持有。
4. 核对编号、取消和准备期限后发布密码回复通道、新 Source 与 Active 阶段，再调用原有 `live::run_gui`。发布只变更内存引用，不在全局会话锁内枚举、写盘、启动 Source 或等待线程。
5. 准备失败/取消时清理本次密码服务及新建 Source；复用的持续预览不停止。确认收尾后释放匹配编号的占用并发 `finished`。进入 Active 后沿用原有停止与持续预览规则。

`session.rs` 集中预留、阶段、期限、按编号停止和释放；`stream_start.rs` 负责后台准备与串流；`configuration.rs` 负责配置、来源预览/开关及发现的后台命令。前端 busy、PCM_READY、遥测及密码状态仍分别表达，不用一个阶段替代这些不同观察结果。

## 准备期限与迟到结果

Preparing 使用 **15 秒**预算，包含枚举、设置、密码服务初始化及 Source 稳定等待；Source 原有稳定等待最多 8 秒，受准备总预算约束。独立监控线程每 10 ms 检查阶段及期限，也检查停止/退出给出的更早期限。

- 正常取消让工作线程在步骤边界退出；停止命令只持有短会话锁并设置原子标志。
- 到期仍未确认准备工作结束时，发送 `START_TIMEOUT`；如果先到的是停止期限，使用 `STOP_TIMEOUT`。占用保持，后续连接/配置明确拒绝，提示重启。
- 迟到枚举结果不能继续进入下一步，过期准备不能发布 Active，迟到收尾不能清除新编号，结束事件只认领一次。
- 超时占用保守地保留至重启，即使旧调用后来返回也不自动开放重试。这样最多保留一份未结束的会话准备，反复连接不会新增枚举线程。

普通停止不能安全强杀任意 WASAPI/文件系统调用。上述预算决定程序停止等待/报告错误的时机，不是操作系统硬实时保证；监控线程调度及事件投递也有实际延迟。应用退出继续使用已有独立进程退出兜底。

## 配置与设置提交

所有设置保存、实时映射、左右互换、发现、预览及采集开关共用一个配置操作占用。在短会话锁内登记后释放锁，再启动后台工作；重复操作直接返回忙碌，不排出无界后台任务。Preparing 期间拒绝配置/来源操作，配置操作未结束时拒绝新连接。Active 期间保留实时映射及左右互换。

`set_mapping` 在后台枚举，检查原会话仍有效后保存；已有配置占用保证期间端点不会被另一配置操作改掉。停止会话不等待枚举，枚举迟到后不能把旧映射应用到下一次连接。保存与路由发布使用独立快照和克隆的控制对象，文件 I/O 不持有全局会话/Source/设置快照锁。Source 的切换/停止仍可能持有其对象锁，不阻碍会话取消标志。

`Settings::save_checked` 在真实暂存写入前后检查取消，成功替换 `settings.json` 后才发布内存与运行路由。写入失败或提交前取消保留原设置；失败后可重试，暂存文件不持续累积。

**文件替换成功是设置的提交点。** 已进入的系统 rename 无法通过原子标志撤销；恰在替换期间收到取消时，已提交偏好仍同步到内存，随后不发布已取消会话。旧写入尚未返回时继续持有占用，避免后来操作抢写同一个暂存文件或被迟到旧写覆盖。没有承诺取消会回滚已经保存的偏好。

配置/初始化命令本轮没有统一新增 15 秒响应上限：若其驱动调用卡住，命令可能仍在等待，但它不持有全局会话锁，配置占用继续阻止重复累积。`initialize` 的独立枚举也没有纳入本次准备预算。

## 前端与日志

`stop_stream` 必须携带 `sessionId`，只取消该编号。返回编号前点击停止会先保留意图，取得可信编号后补发；不会用早到事件猜编号。卸载时取消已知编号，卸载后迟到返回的编号也单独取消。旧停止命令迟到执行不能停止新会话，密码重试、早到 finished 和 512 条缓冲上限继续保留。

超时通知使用常量错误文本，不读取设备文件、不增加周期性日志。普通故障沿用每文件 **64 KiB**、目录 **256 MiB/256 文件**及全进程最多 **8 个**限时持久化/通知任务；页面历史和报告限制不变，见[日志限制](log-retention.md)。没有新增音频包重排、样本修改或左右互换算法。
