# stderr 读取状态与统一停止期限

本轮处理仓库复查中的两个缺口：读取 stderr 失败被当成普通结束，以及后端退出之后仍有无限等待的收尾步骤。CI 继续暂缓。

## stderr 的独立状态

`live/protocol.rs` 的 `ReaderState` 与协议故障、认证故障和日志写入状态分开保存：

| 状态        | 含义                                                       |
| ----------- | ---------------------------------------------------------- |
| `reading`   | 读线程仍在处理或等待数据                                   |
| `eof`       | 正常读到管道结尾                                           |
| `failed`    | 读取失败，保存 `kind`、`os_error` 和含操作上下文的错误文本 |
| `cancelled` | 主动取消后结束；Win32 995 仅在已请求取消时归入此状态       |

读取错误使用 `BACKEND_STDERR_FAILED`，包含 `读取后端 stderr / ReadFile`、原始 OS 错误和 Win32 来源。正常 EOF 不生成读取错误。就绪之前返回明确读取故障；就绪之后，音频处理在继续转换/入队之前检查它并停止本次会话。

走到既有报告阶段后，报告新增 `stderr_reader`、`stderr_error` 和 `shutdown`；握手/就绪之前失败仍直接返回错误，不生成完整会话报告。原有首个协议故障仍优先，读取错误不覆盖认证故障，也不混入 `protocol_log_status`。主动点击停止仅隐藏预期的“已取消建立流/启动采集已取消”；真实协议、采集、读取和收尾故障继续显示。

## 共用停止预算

`shutdown::Budget` 在首次停止请求记录 **15 秒**截止时间。重复点击停止、退出或进入后续步骤只能缩短期限，不能重置它。GUI 停止命令和 CLI Ctrl+C 都先记录预算再置停止标志；自然结束或失败则在开始收尾时记录。

正常停止保持既有顺序：解除订阅、排出滤波器尾帧、关闭唯一 PCM 发送端、排空已接受的 PCM，再由后端完成尾部静音及 TEARDOWN。没有重排采集包、修改 PCM 内容或改变左右互换方式。

后端优雅退出、强制终止及状态轮询、PCM/stderr 线程、DACP、诊断日志和报告写入使用同一期限。预留最后一秒用于终止和后续收尾，不再把整段时间耗在等待后端。核心流程保留最后 250 ms 给桌面密码管道及最终通知；日志仍最多共用 250 ms，报告写入最多等待 250 ms，并受总期限约束。

后端使用 Windows Job Object，配置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。超出优雅退出期限时终止所属进程树，再轮询退出状态；错误返回和守卫销毁也会关闭 Job，不调用无期限 `Child::wait`。Job 配置失败时终止刚创建的子进程并返回带操作上下文的错误。

线程只在确认完成后 join；到期保留明确的未完成状态。取消同步 I/O 会请求 Windows 唤醒管道等待，但不把取消请求成功视为线程已退出。

## 超时后的资源保护

- Source 停止超时保留旧对象与线程句柄。再次请求沿用首次期限，旧 Source 处于停止中时不能被当成健康来源复用，也不创建第二份采集资源。
- 协议/PCM/DACP/密码线程或后端未确认退出时，桌面保留旧会话占用并提示重启。界面收到结束错误后可以退出；新的连接会被明确拒绝，避免反复产生未退出资源。
- 报告、故障文件及收尾通知的后台任务全进程最多 **8 个**。到期不再等待，名额由实际结束的任务释放；达到上限直接返回错误。单报告 1 MiB、故障文件 64 KiB 和现有文件/目录保留限制不变。
- 应用退出先启动独立等待线程，再处理 Engine 锁、唤醒状态、Source 和会话。到期通过进程退出兜底；即使正常收尾后主事件循环没有处理退出，也沿用原期限退出。父进程退出会关闭 Job 句柄，终止仍在其中的后端。

读取或协议首因不会被报告保存失败覆盖。超时报告同时记录强制终止、后端状态读取错误、各工作线程完成标志；`backend_exit=null` 表示没有取得退出码，不能解读成成功。

## 验证与边界

新增无音频设备回归覆盖：读取前/后就绪错误、Win32 232 来源、EOF/取消区别、协议与认证首因、运行期停止入队、共享期限不续期、阻塞 Source 保留与重试、真实 Windows 子进程 EOF/强制退出、Job 守卫、真实匿名管道释放、通用阻塞读写、报告通知阻塞、密码提示阻塞，以及用户停止后仍展示读取/收尾错误。

验证结果记录在维护进度。测试使用本地模拟进程和管道；没有连接 HomePod，没有执行 WASAPI 驱动故障注入、真实磁盘长时间卡顿或完整桌面退出实机长测。

这是程序等待预算及应用退出兜底，不是 Windows 调度/驱动的硬实时保证。普通“停止串流”不会强杀整个应用，也不能安全终止任意 Rust 回调；未结束资源会阻止重连。已进入的文件写入可能在等待到期后才完成，报告文件也可能晚于界面错误落盘。应用强制退出可能丢失尚未完成的日志或报告。

Windows API 语义依据：[CancelSynchronousIo](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelsynchronousio) 明确取消不等待操作完成；[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 说明 Job 的进程组管理与句柄关闭终止规则。
