## 已完成：时长预算、缓冲复用与性能基线

- `audio_queue.rs` 给 Source 和 PCM 两级队列各自设置 640 ms 音频预算，按每块帧数/采样率计算，包含消费者处理中或管道写入中的块；另设 256 块硬上限限制极小包。
- RAII 在成功、队列拒绝、断开、消费失败及积压丢弃时归还时长；Source 仍在分支溢出时结束订阅而保留预览。
- PCM 写线程归还字节 Vec，回收池最多 32 个；会话复用左右交换数组。Source 仍复制采集数据，没有追求零拷贝。
- 报告增加预算、队列峰值和 PCM 新建/复用计数；增加阻塞写入、消费失败、可变块/采样率预算和声道互换回归。
- 新增显式运行的 Release 合成基线和比较脚本，可由调用者选定 p95 回归阈值；原始 JSON 位于忽略目录，方法与本轮数值见 [性能基线](performance-baseline.md)。

同机前后 p95 的三轮中位变化约 -7% 至 +5%，没有一致的大幅耗时改善；修改后每轮新建 PCM Vec 1–3 个，复用 459–1999 次。计数不是整机堆分配或 CPU 测量。640 ms 是每级最大未完成音频容量，不是实际播放延迟。
