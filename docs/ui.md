# AirPlay Bridge 桌面应用

桌面程序使用 Vue 3 / TypeScript、Tauri 2 和 Rust 音频核心库。项目架构、构建依赖与 CLI 说明见 [项目介绍](../README.md)。

## 运行

按照 [构建指南](building.md) 构建后启动 `dist/airplay-bridge.exe`。同目录的原生后端与 DLL 必须保留，界面资源已嵌入 GUI exe。运行需要 Microsoft Edge WebView2 Runtime。

电脑与接收端需位于可互相访问的局域网。设备发现与串流依赖局域网通信，防火墙或无线网络隔离可能影响连接。

## 页面与操作

### 播放

底部固定操作区提供音频来源选择、开始/停止串流和刷新按钮，在播放与设置页面均可操作。音频来源列表向上展开，选择框底边显示总峰值电平，格式右侧显示 dBFS。

首次启动或没有有效的上次来源记录时，显示“请选择音频流来源”，不自动选择 Windows 默认设备，也不启动采集。手动选择后开始电平预览并保存来源；下次启动仅恢复仍有效的来源。

选择录音设备或 Playback 播放设备作为音频来源。录音设备采集输入信号，Playback 采集所选输出端点正在播放的音频；来源选定后显示电平，无需先连接扬声器。

来源选单分为独立的“播放设备”和“录音设备”区块，以扬声器／麦克风图标及说明区分，各组内按名称排序。选中后，来源选择框仍显示“播放”或“录音”类型标签。

刷新并选择 AirPlay 设备，点击开始串流。若接收端要求访问密码，固定音频来源操作区上方弹出输入框，提示“输入 {设备} 的 AirPlay 密码”。输入框自动聚焦，回车确认；密码错误后全选原输入供重试。密码只供当前认证使用，不保存到配置。

设备区域提供音量、静音及连接状态。立体声设备需先在 Apple 家庭 App 中组成一对；连接后可交换左右扬声器位置。该操作独立于来源输入声道映射，单设备不显示交换按钮。

播放提前量控制请求的协议播放时间偏移，实际值受设备能力限制。它不会自动同步外部播放器的视频或歌词。

### 设置

通过窗口右上角的齿轮进入设置。设置标题靠左，返回播放按钮与子页面 tab 位于同一行；滚动页面时，这一栏固定在顶部。运行统计、技术详情与日志保留原有布局。

| 子页面 | 内容 |
|---|---|
| 常规 | 关闭窗口动作、保持系统唤醒、外观、播放提前量与左右输入声道映射 |
| 运行统计 | 累计传输计数及会话统计 |
| 技术详情 | 音频格式、电平、处理流水线、漂移与发送 Buffer |
| 日志 | 会话输出、日志路径和额外诊断开关 |

来源设备的默认格式与 WASAPI 实际工作格式可能不同；界面分别显示。比如默认格式是整数 PCM，驱动提供的共享采集流仍可能是 float32。

Buffer 是发送端的 PCM 预读深度，与播放提前量不同。标注“下次连接生效”的设置需在重新串流后应用。

默认关闭窗口收起到托盘并继续运行。再次启动 exe 会恢复已有实例，托盘右键“退出”关闭应用。可将关闭动作改为退出。

“保持系统唤醒”默认开启，启用后在应用运行期间阻止系统自动睡眠，包括托盘和未串流状态；不要求屏幕常亮。关闭开关或退出应用会释放请求。

## 采集与串流生命周期

选择来源后，Rust 创建持续运行的 WASAPI 采集器。GUI 预览与串流共用该来源；后端准备好接收 PCM 后，串流订阅当前音频，每次只接收新数据。

停止串流解除订阅，采集器继续提供预览电平。切换来源或退出应用才释放采集器。每个串流会话拥有独立的重采样状态、漂移控制和发送队列。

音频与诊断使用不同的有界队列。诊断写盘跟不上时会丢弃并统计诊断记录，不阻塞音频；音频队列或时间线异常会明确报错。

## 配置与日志

配置、设备缓存、认证方式记录和 GUI 日志位于：

```text
%APPDATA%\AirPlay Hub
```

认证方式记录不保存密码。密码经本机命名管道交给原生后端，不写入进程参数。

默认记录关键故障与必要上下文。详细会话日志可记录协议、音量、漂移和流水线数据；逐包采集诊断另记录包位置、时间戳、帧数、峰值、样本指纹及处理耗时，不保存原始音频。

逐包日志每约 8 MiB 轮转，保留当前文件和三段历史文件。该限制按会话应用，不代表全部日志总大小有上限。分享日志前检查设备名称、网络地址、端点 ID 和本机路径，并按需脱敏。

| `src/App.vue` | 页面、交互与 Rust 事件订阅 |
| `src/style.css` | 布局和主题 |
| `src-tauri/src/main.rs` | 桌面生命周期、配置、设备发现和会话控制 |

| `src-tauri/src/awake.rs` | Windows 系统唤醒请求 |
| `../airplay-core/src/source.rs` | 共享来源采集器与订阅 |
| `../airplay-core/src/live.rs` | 音频发送流水线与后端进程 |
| `../airplay-backend/` | 原生 AirPlay 后端及 Windows 适配 |

GUI 直接链接 `homepod-test` Rust 库，启动的协议后端是 `airplay-backend.exe`，不通过 CLI exe 管理采集。

## 构建

在项目根目录运行：

```powershell
.\Build-UI.ps1
```

依赖已下载后可加 `-Offline`；`-Release` 优化 Rust 桌面应用；`-SkipBackend` 仅在已有可用后端及 DLL 时使用。完整依赖和自定义工具路径说明见 [根目录 README](../README.md)。

单独启动 Vite 开发服务器仅提供前端环境，不能代替 Tauri 与原生音频后端。

Playback 逐包诊断还记录释放前原始缓冲的各声道峰值、非零字节数和非有限采样数，以及映射选择、Windows 端点电平和读数年龄。`capture_start` 中 `capture_wait=wasapi_event` 表示使用事件驱动回采；这些统计不保存原始音频。

VoiceMeeter 播放设备出现“系统电平正常，但本软件只有短暂声音后全零”时，检查正在使用的 VAIO 内部延迟及控制面板缓冲统计。一次实机对照中，VAIO3 的 latency 为 768 时独立采集有 11/16 次失败，调到默认 7168 后全部通过；随后按低延迟需求改为 1536，30 次独立重开、60 秒连续采集及 6 次项目来源初始化也均通过，项目未触发重建。当前采用 1536，48 kHz 下约为 32 ms 的 VAIO 内部延迟，不是 AirPlay 总延迟。需在 VoiceMeeter 主界面右键对应虚拟输入标题保存延迟，单独控制面板的临时修改可能被引擎重启覆盖。此结果不代表所有设备都使用同一延迟，完整验证和局限见 [播放回环排查](playback-loopback.md)。

旧 `%APPDATA%\com.airplaywin.bridge` 的数据在首次启动时复制到 `AirPlay Hub`，仅补充新目录缺失的文件，不覆盖已有配置。旧目录保留作为备份，迁移完成后不会反复恢复已删除的日志。


### 采集控制、外观与启动

底部音频来源左侧的采集开关可以在未串流时停止持续 WASAPI 采集，释放音频设备；停止串流本身仍保留采集与电平预览。手动关闭采集后点击开始串流会自动恢复采集，等待至少 500 ms 的连续交付、无新增不连续/时间戳错误/缺口修复，再开始 AirPlay 握手。正常静音也计入就绪；8 秒仍未稳定则报错，不连接设备。串流期间不能关闭采集，可先停止串流。

窗口首次打开时居中。常规设置提供浅色、深色和跟随系统，跟随系统会响应 Windows 主题变化。开机自启默认关闭，由用户开关写入当前用户的 Windows Run 项 `AirPlay Hub`，不需要管理员权限。启用后需保留 exe 所在位置；移动软件后重新启用以更新路径。自启只打开应用，不自动开始串流。

音频预览启动现在等待采集就绪后返回。`logs/source-startup.jsonl` 独立记录每次来源初始化、前 10 秒的每秒采集摘要及退出原因，无需先串流或启用详细日志。文件超过约 2 MiB 时在下一次来源启动时轮转，保留一个旧片段；不保存原始音频。`event_timeout_packets` 统计通知未到但缓冲中有包的补读次数。

发布用代码与示例不包含开发机器的设备名、地址或端点标识。日志落盘及界面日志窗口默认隐藏设备名称、IP、用户路径、公钥和 MAC，UUID、采样格式、时序与计数保留。内部协议控制保留真实地址；连接信息／认证缓存是本机运行数据，不作为公开日志打包。详细日志的原始响应 body 不再保存，以避免十六进制编码绕过文本脱敏。旧日志不会自动改写，分享旧日志前仍需自行检查。

音频来源选单按 Playback／Recording 分组，各组独立按真实名称排序，忽略大小写并对数字进行自然排序，同名时按端点 ID 稳定排列。
