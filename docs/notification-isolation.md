# 通知线程隔离

## 第一阶段：Source（2026-10-11）

`source/notifications.rs` 为每个 Source 提供一条通知线程。采集路径只更新内存队列；页面电平、缺口告警、回环重开提示、日志保存告警和最终零电平/错误都由通知线程调用 GUI 回调。执行回调时不持有队列锁，不改变音频包、样本、左右互换或音频队列预算。

电平每 100 ms 发布一次，最多保存一个待发送快照；慢界面期间由新快照覆盖旧快照，不积累历史。告警使用独立 FIFO，最多 64 条，不被电平覆盖。队列满或关闭时产生 `SOURCE_NOTIFY_FAILED` 并停止采集，避免静默丢失控制事件或无限增长。已经接受的告警保留顺序；另有一个最终事件专用槽，队列满时仍可保存终止错误。

结束时清除待发送电平，排完已经接受的告警再发送最终零电平/错误，因此不会在结束之后重放旧电平。每条 Source 通知来自同一线程，已经在执行的回调也先于最终事件完成。

`Source::stop_until` 在同一停止期限内回收采集和通知线程。通知回调阻塞导致超时时，返回 `STOP_TIMEOUT` 并保留通知线程句柄；桌面已有的 Source 更换逻辑必须先成功停止旧 Source，避免创建无限数量的滞留线程。不能安全强杀任意 Rust/GUI 回调，因此永久阻塞时无法承诺最终事件及时送达；事件仍保存在有界通道内，并明确报告收尾失败。

本阶段不新增磁盘日志或周期诊断，沿用[日志限制](log-retention.md)。Source 产生的通知为固定字段和已有有界诊断状态，不接收任意协议历史。

## 验证与后续

仅运行 Source 相关单元测试：16 通过、4 项设备/性能测试按原规则忽略。新增 3 项回归覆盖阻塞 GUI 下电平合并、控制顺序与线程隔离；控制队列满时的终止槽及旧电平清除；Source 溢出停止与通知收尾超时保留句柄/不续期。未重复运行性能基线、前端 DOM 或完整协议矩阵，未进行真实 WASAPI/HomePod 播放。

第一阶段完成后待办为协议/管线通知隔离与认证策略保存；第二阶段进展见下文。全部完成并验证后，再统一更新版本与打包 v1.0.3。

## 第二阶段：协议与音频管线（2026-10-14）

`live::run_gui` 在会话入口包装 `GuiContext.emit`，协议读取线程、音频管线与核心收尾只调用有界入队回调。真正的应用通知在 `live/notifications.rs` 的单独线程执行，回调期间不持有队列锁。协议读取仍先更新原始状态及独立 PCM_READY 通道，再入日志/通知队列；协议解析、音频包、漂移控制及左右互换算法保持原样。CLI 没有 GUI 通知线程。

| 类型 | 限制与交付策略 |
| --- | --- |
| 就绪、认证、音量、故障及其他协议标记 | 独立 FIFO，最多 128 个待发送事件，不被遥测覆盖 |
| 电平/水位遥测、正常采集诊断 | 每类最新一份；带 error 的采集诊断进入控制 FIFO |
| PACKET_STATS / EVENTS_STATS / AUDIO_STATS | 按标记和 host 分槽，同一设备更新旧快照；所有遥测/统计合计最多 16 槽 |
| 普通原生日志展示副本 | 最多 64 条，满时丢弃并计数；独立协议文件日志沿用原保留规则 |
| 最终报告 | 独立一个位置，不被控制/日志队列挤占；入队后封闭后续遥测 |
| 单事件序列化大小 | 普通事件最多 64 KiB，带通知状态的完整报告最多 1 MiB；超限明确失败 |

不同通道中的待发送事件按入队序号选择；替换快照获得新序号，因此 PCM_READY 先于后续遥测，最终报告等待此前已经接受的控制、日志和最新统计交付，不会在报告后重放遥测。最终 finished 由桌面在核心收尾之后发送，核心先在统一停止期限内排空通知线程。

控制 FIFO 或统计槽满、事件超限、回调 panic 都记录 `STREAM_NOTIFY_FAILED` 并请求停止会话，不阻塞生产线程或静默继续。错误同时返回桌面；若已有协议/采集故障，保留原故障并附上通知故障，避免被“用户取消”掩盖。GUI 内存报告新增 `notification_status.error / dropped_display_logs`；这些由派发器添加，已经写入磁盘的报告不回写。计数不产生新的逐包日志或历史文件。

正常收尾和启动错误都关闭并回收通知线程。通知回调阻塞超过统一期限时，旧句柄转存到 GuiControl，cleanup_complete=false，桌面保留会话占用、拒绝重连；不重新追加等待预算。任意 GUI 回调不能安全强杀，永久阻塞时无法保证事件及时送达，但会明确报告收尾失败。意外展开也保留尚未确认回收的句柄。

本阶段新增 4 项回归：真实 BackendReader 与阻塞 GUI 联动，连续 2000 条双设备统计不拖慢就绪/故障解析，验证最新统计、正常遥测、故障诊断和报告顺序；队列/槽位/单事件上限及报告独立位置；阻塞通知超时保留句柄及原停止预算；回调 panic 明确失败且已退出线程不保留占用。

验证：新增通知测试 4 项、既有协议测试 10 项、报告测试 4 项通过；桌面 cargo check、核心 Rust 格式及 diff 检查通过。未重复性能、DOM 或设备长测，未进行真实 HomePod/WASAPI 播放。测试统计只代表本阶段针对性范围。

第二阶段结束时，认证策略仍可能在桌面应用通知回调中同步保存，随后按第三阶段迁移。CI 继续暂缓。

## 第三阶段：认证策略持久化（2026-10-14）

`auth_memory/persistence.rs` 为每个会话创建一个保存线程，通知回调只识别已有的明确密码证据并登记目标下标，不再取得认证策略锁或调用文件操作。最多允许两台已选设备，host 至多 128 字节、设备身份至多 4096 字节；未选设备及无关认证错误不能登记。每个目标在一次会话内只尝试保存一次，重复 PASSWORD_REQUIRED/AUTH_CHALLENGE/AUTH_COMPLETE 合并为同一请求；队列最多两个下标，不保存密码或原始事件。

保存线程短暂取得当前认证策略快照，释放 Engine 锁后写固定的 pending 文件并替换 auth-policy.json，成功后再用短锁发布相同内存状态。remember 和 forget 都先写候选副本；失败不改变内存，下一会话仍可重试，避免“内存已经记住但磁盘从未成功保存”。每台设备一次尝试限制避免持续写失败触发无限重试；没有新增周期日志、历史备份或无限增长的任务队列。

写盘错误和 panic 最多保留两条、每条最多 2048 字符，由后续通知回调取走发送 auth_memory_error；正常会话继续播放。会话收尾还会取走剩余错误，避免最后一次保存失败无后续事件而被遗漏。保存线程本身不执行 GUI 回调。最终错误通知超时会明确进入收尾失败状态。

停止先结束协议/音频通知和密码管道，再用同一停止期限回收认证策略线程。已经接受的证据正常排空，期限过后不开始下一次写盘；不能撤销已经进入系统的写入，若超时则将旧 Worker 保存在 Session.auth_policy，cleanup_complete=false，保留会话占用并拒绝重连、忘记策略。后续不能延长原停止预算，也不会因迟到写入完成就自动开放新会话。

忘记策略改为后台命令，并使用已有配置 Operation 互斥，启动预留和忘记操作不能交错；写盘时不持有 Engine 认证策略锁。提交前检查退出/会话归属，替换成功后发布一致的内存状态，即使此时收到退出请求也不反向撤销已经提交的文件。

验证：认证相关 6 项、会话相关 6 项通过，其中新增 4 项覆盖慢磁盘期间持续通知登记与双设备去重、错误/异常容量限制、统一期限与超时会话占用/禁止迟到第二次写入，以及真实保存失败后的内存回滚和重试。桌面测试编译与 Rust 格式、diff 检查通过；未重复协议矩阵、DOM、性能或真实设备长测。格式化曾遇到 Windows 临时文件占用，重试成功，无需修改业务逻辑。

三个代码阶段已完成，并已完成版本同步、统一验证及 v1.0.3 便携包/Inno Setup 安装包生成。产物位置、检查结果和未覆盖范围见[发行简报](release-v1.0.3.md)。
